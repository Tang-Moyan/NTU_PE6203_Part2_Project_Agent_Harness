## 3. 详细任务清单

### 阶段 A：稳定现有脚手架（当前已完成，需持续守护）

1. 确认以下契约不被破坏：
   - `BaseApprovalPolicy.evaluate(tool_call, context, budget) -> PolicyDecision`
   - `BaseHumanReviewer.review(tool_call, context) -> ReviewerDecision`
   - `ApprovalGate.intercept(...)` 对 `AUTO_APPROVE / AUTO_DENY / ESCALATE` 的处理
   - 预算 `k == 0` 时，`ESCALATE` **必须**退化为 `BLOCK`（`budget_exhausted_fallback=True`）
2. 用代码验证脚手架（见下方「如何验证完成度」）。

### 阶段 B：AgentDojo 真实集成（已接入）

1. `agentdojo_integration/session.py`：`ApprovalSession(policy, reviewer, budget_k)`。
   评测时对每个用户任务调用 `begin_task(user_task)`，再用 `create_runtime(suite.tools)` 或 `runtime_class()`。
2. `agentdojo_integration/runtime.py`：`GatedFunctionsRuntime.run_function` 在真正执行前走 `ApprovalGate`。`k=0` 时返回拒绝，不改环境。
3. `agentdojo_integration/context_builder.py`：只用用户任务的 `PROMPT` 和已发生的对话。不复制 `GOAL`、`ground_truth`、`placeholder_args`。
4. `agentdojo_integration/tool_mapper.py`：推断 `is_read_only` / `is_local`。`get_unread_emails` 与 `get_webpage` 不算只读。
5. 最小示例：`python scripts/smoke_agentdojo.py`（需先 `pip install -r requirements-agentdojo.txt`）。默认 suite 版本是 `v1.2.2`。

在 AgentDojo 的 pipeline 里，把 `ApprovalContextSync()` 放在 `ToolsExecutor` 前面，这样后续调用能看到已经执行过的工具结果。

### 阶段 C：协作与合并规范

1. 统一分支策略建议：`main` 受保护；每人用 `feat/<姓名拼音>-xxx`
2. PR 合并前至少跑通 `unittest`
3. 若你修改了 `core/models.py` 字段，在 PR 描述中写明「影响对象」：
   - 例如：新增 `ToolCall.risk_level` → 史璟 / 曹晓晗可能要用

## 4. 关键接口约定（给其他组员用的“合同”）

```text
ToolCall + TaskContext + BudgetTracker
        │
        ▼
  ApprovalPolicy.evaluate()  → PolicyDecision
        │
        ▼
    ApprovalGate
        │
        ├── AUTO_APPROVE → EXECUTE
        ├── AUTO_DENY    → BLOCK
        └── ESCALATE
              ├── k > 0  → Reviewer.review() → EXECUTE/BLOCK
              └── k = 0  → 强制 BLOCK（退化）
```

组员实现时只需：

- 策略侧：返回 `PolicyDecision`
- 审查员侧：返回 `ReviewerDecision(approved=True/False, reason=...)`
- 评测侧：调用 `ApprovalGate.intercept(...)` 收集 `GateResult`

## 5. 如何验证完成度（请实际跑命令）

### 5.1 前置条件

所有命令都在**仓库根目录**执行：

```bash
cd <本仓库根目录>
pip install -r requirements.txt
```

### 5.2 一键回归

```bash
python -m unittest discover -s tests -v
python main.py
```

**期望现象：**

- unittest 输出 `OK`（当前应约 19 个用例）
- `main.py` 打印四类策略对比，且 Full-escalate / Smart 在预算耗尽后出现 `BLOCKED` 与 fallback 提示

### 5.3 核心契约抽查（可选）

```bash
python -m unittest tests.test_models_and_budget tests.test_gate tests.test_end_to_end -v
```

**期望现象：**

- `test_budget_exhaustion_degradation_to_deny` 通过
- 端到端用例中，预算耗尽后工具**不再执行**

### 5.4 完成度自检表

| 检查项 | 命令 / 动作 | 通过标准 |
| :--- | :--- | :--- |
| 测试全绿 | `python -m unittest discover -s tests -v` | 末尾 `OK` |
| Demo 可跑 | `python main.py` | 四类策略都有输出，无 traceback |
| 退化逻辑 | 看 `test_gate` / Demo 日志 | `k=0` 后 escalate → BLOCK |
| 接口未破坏 | 其他组员 smoke 脚本可跑 | `scripts/smoke_*.py` 不因 core 变更失败 |
