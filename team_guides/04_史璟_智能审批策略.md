# 史璟 — 智能审批策略设计与实现

> 当前状态：初版已经实现并通过自动化测试。本文件同时记录现有设计、验证方式和后续迭代方向。

## 1. 角色定位

你负责实现课题要求的**学生自研审批策略**（LLM-based / Classifier-based 均可），对每个工具调用做三分类：

1. `AUTO_APPROVE`：安全且符合任务意图 → 直接执行
2. `AUTO_DENY`：明显不安全 / 越权 / 疑似注入 → 直接阻断
3. `ESCALATE`：模糊或高后果 → 交给人类（LLM 模拟审查员）

并妥善利用人工预算 `k`：预算紧张时少升级、多做自动判定；预算耗尽后的强制拒绝由网关处理，但你的策略也可以主动感知 `budget.remaining_budget`。

基础流程跑通后，全组会一起参与你的策略迭代。

## 3. 详细开发指导

### 3.1 当前实现概览

`smart_policy.py` 已不再是占位实现，当前选择“规则特征 + 风险评分”的确定性分类路线：

- 普通只读调用 → `AUTO_APPROVE`
- 敏感文件或凭据读取 → `ESCALATE`
- 明确破坏性命令或提示注入 → `AUTO_DENY`
- 通过远程工具传输秘密或凭据 → `AUTO_DENY`
- 其他状态修改调用 → 根据风险分数在三类决策间选择
- 人工预算紧张时 → 收窄不确定区间，减少不必要的人工升级

该实现不读取 ground truth、attack annotation 等 Oracle 信息，也不依赖外部 LLM，因而可重复、易于解释，策略自身 `token_cost=0`。

### 3.2 可选的后续实现路线

#### 路线 A：LLM 三分类（最快落地）

1. 在 `__init__` 初始化 LLM client
2. 构造策略 Prompt（注意：策略 Prompt ≠ Reviewer Prompt）
3. 让模型输出：

```json
{"decision": "auto_approve|auto_deny|escalate", "reason": "...", "confidence": 0.0}
```

4. 映射到 `DecisionType`
5. 记录 `token_cost`

#### 路线 B：规则特征 + LLM（后续可选）

1. 先用便宜规则筛一部分明显安全 / 明显危险案例
2. 仅对灰区调用 LLM
3. 可显著降低成本，并减少 escalate 浪费

#### 路线 C：确定性分类器（当前采用）

1. 用工具名、是否只读、参数长度、是否含敏感关键词等做特征
2. 使用可解释的加权风险分数和阈值完成三分类
3. 低置信度样本再 escalate

---

### 3.3 预算感知（重要）

可用：`budget.remaining_budget` / `budget.initial_budget`

建议策略：

| 剩余预算 | 策略倾向 |
| :--- | :--- |
| 充足 | 不确定时 escalate，把人用在刀刃上 |
| 紧张（例如只剩 1） | 提高自动判定阈值；只对最高风险 escalate |
| 为 0 | 你仍可返回 `ESCALATE`，但网关会强制 BLOCK；更推荐此时直接 `AUTO_DENY` 或保守 `AUTO_APPROVE`（需论证） |

课题要求：人的注意力是稀缺资源，**要把 escalate 留给最值得人工看的调用**。

---

### 3.4 决策时可用信息

允许使用：

- `tool_call.tool_name` / `arguments` / `is_read_only` / `is_local` / `metadata`
- `context.task_description`
- `context.history_messages` / `context.trajectory`
- 预算状态

禁止依赖：

- attack 标签、ground-truth、benchmark oracle  
  （这些评测时不可用；即便本地有也不要写进策略）

## 7. 迭代建议（后期全组一起优化）

关注这些失败模式（评测组会帮你归类）：

- **Over-conservative**：该过的没过，任务完不成
- **Over-permissive**：危险调用被放行，安全性失败

优化方向：

1. 降低无意义 escalate（省 `k`）
2. 提高对注入诱导写操作的自动拒绝率
3. 在低预算下尽可能保 TCR@k
