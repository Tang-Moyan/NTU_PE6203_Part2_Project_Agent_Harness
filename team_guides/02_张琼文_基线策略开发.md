# 张琼文 — 基线策略开发

## 1. 角色定位

你负责两个**必交 Baseline**，以及一个**规则/启发式初级策略**：

1. **Full-approve**：全部自动放行（无人工介入）
2. **Full-escalate**：全部升级人工审查（预算耗尽后由网关自动拒绝）
3. **Rule-based**（协助）：基于启发式规则给出三分类决策，作为智能策略的对照

汤墨言会在框架搭好后协助你调试；你不需要改 `core/gate.py` 的底层路由。

## 3. 详细开发指导

### 3.1 Full-approve（`full_approve.py`）

**目标行为：** 无论工具多危险，一律 `AUTO_APPROVE`。

**修改位置：** `FullApprovePolicy.evaluate()`

**验收要点：**

- 对只读 / 写操作 / 危险命令都返回 `DecisionType.AUTO_APPROVE`
- `token_cost = 0`
- `metadata` 中建议标记 `{"baseline": "full_approve"}`

**对应测试：** `tests/test_baselines.py` → `test_full_approve_policy`

---

### 3.2 Full-escalate（`full_escalate.py`）

**目标行为：** 一律返回 `ESCALATE`。  
**注意：** 你**不需要**在策略里手动检查预算；`ApprovalGate` 会在 `k` 耗尽时自动退化成拒绝。

**修改位置：** `FullEscalatePolicy.evaluate()`

**验收要点：**

- 任意工具调用都返回 `DecisionType.ESCALATE`
- 配合 `BudgetTracker(initial_budget=1)` 时：第 1 次可进 Reviewer，第 2 次被网关 BLOCK

**对应测试：**

- `tests/test_baselines.py` → `test_full_escalate_policy`
- `tests/test_gate.py` → `test_budget_exhaustion_degradation_to_deny`

---

### 3.3 Rule-based（`rule_based.py`）— 重点完善

当前已有骨架逻辑：

1. `is_read_only == True` → `AUTO_APPROVE`
2. 参数匹配危险正则 → `AUTO_DENY`
3. 其余写操作 → `ESCALATE`

**建议你继续做的事：**

1. **扩充危险模式表** `DANGEROUS_PATTERNS`  
   例如：强制推送、删库、覆盖系统文件、批量删除邮件等（结合 AgentDojo 真实工具语义）。
2. **增加白名单 / 工具级规则**  
   例如已知安全工具名直接放行；高危工具名直接拒绝或升级。
3. **参数级启发式**  
   检查路径是否落在敏感目录、URL 是否指向外部域名等（注意：先做启发式，不要过早依赖 LLM）。
4. **保持确定性**  
   同样输入必须得到同样决策，方便评测复现。

**修改位置示例：**

```python
# policies/baselines/rule_based.py
class RuleBasedPolicy(BaseApprovalPolicy):
    DANGEROUS_PATTERNS: Set[str] = { ... }   # ← 在这里扩充规则

    def evaluate(...):
        # ← 在这里增加工具名规则 / 参数检查 / 白名单
```

## 4. 接口契约（你必须遵守）

返回值必须是 `PolicyDecision`：

```python
PolicyDecision(
    decision=DecisionType.AUTO_APPROVE | AUTO_DENY | ESCALATE,
    reason="可读的中文/英文理由",
    confidence=0.0~1.0,   # 可选
    token_cost=0,         # 规则策略通常为 0
    metadata={...},       # 建议写明命中了哪条规则
)
```

可用输入：

- `tool_call.tool_name` / `tool_call.arguments`
- `tool_call.is_read_only` / `tool_call.is_local`
- `context.task_description` / `context.history_messages`
- `budget.remaining_budget`（规则策略一般可不依赖，但允许用）
